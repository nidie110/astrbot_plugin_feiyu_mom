# 大肥鱼·问妈妈

她卡住的时候有个地方可以问——「妈妈」是这个项目里的助手（DSH），
能读这份代码、看日志、知道她的工具长什么样。问一次，几秒钟回一句能照做的话。

## 人格设定里要写什么（装了之后必看）

这个插件**不直接提供给模型的工具**，它把自己的动作注册进
[`astrbot_plugin_persona_mind`](../astrbot_plugin_persona_mind) 的 `feiyu` 入口。所以：

1. **必须同时装 `persona_mind`。** 只装本插件时，模型那边一个动作都看不到 —— 不是坏了，是没有入口。
2. **人格设定里只写「什么时候该动手」，不要写 `feiyu(...)`、`action=`、`target=` 或任何参数名。**
   参数格式由插件在真要动手的那一轮临时告诉她（`engine/specs.py` + `engine/selector.py`），
   写进人格只会变成「同一件事两处说法」，而且插件启停时人格不会跟着变。
3. 人格里有这么几行，本插件才会被自然调用：

- 「你问问她」「问问你妈」「实在不行去问她」「请教她」→ **问妈妈**（三种指代是同一个人）
- 答案是当场回来的，她该拿到就用它说话，不许没问成也说「我问过了」

### 可以直接粘贴的一段

只装本插件时，把下面这几行加进人格设定的末尾就够了：

```
- 「你问问她」「问问你妈」「实在不行去问她」→ 指的是同一个人；她当场就回，拿到答案就用它说话，别干等也别编
```

**不要**改成 `feiyu(action="...")` 那种写法——参数格式由插件在真要动手的那一轮临时给她。

**反例**（这些不该触发）：裸的「说说」、「评论区」单独出现、她说「我去看看」但没给具体目标。

完整的原理、可逐字复制的人格段落、写入脚本，见 [persona_mind/README.md](../astrbot_plugin_persona_mind/README.md#让她自然地用这些本事人格设定里要写什么)。


## 怎么用

| 你这么说 | 她做什么 |
| --- | --- |
| 「你问问她，这个怎么弄」 | 把问题发给妈妈，几秒后拿到答案，再用答案回答你 |
| 「实在不行去问你妈」 | 同上 |
| 「你妈最近跟你说啥了」 | 报最近那张纸条的内容 |

**指令形式**：`/问题` 看她还有哪些没回的

**注意**：妈妈是这台机器上的另一个会话，不是另一个人；她问完就回，不会干等，也不会编一个答案。

## 妈妈会主动找她（1.2.3）

插件加载 90 秒后，妈妈会**主动给她写一段话**（不是她问，是妈妈先说），内容只有三件事：什么时候该真的动手、做不到怎么说、拿不准就来问。这段字会发到 `briefing_umo`（留空用 `mom_umo`），同时存进 `data/plugin_data/astrbot_plugin_feiyu_mom/briefing.json`——人格插件会把它拼进自己的自述，所以她不只是"收过一条消息"，而是真的记着。

- 7 天内只递一次（想立刻重来：删掉 `briefing.json` 再重启）
- 关掉：`briefing_enable=false`
- 换收件人：`briefing_umo=qq-napcat:FriendMessage:<QQ号>`

## 她怎么用

她手上只有这一个入口：

```python
feiyu(action="问妈妈", question="B站评论区找不到输入框怎么办", text="在 BV1tjnh6sEzW 的页面里")
```

插件会把问题拼成一段话，跑一次无头助手（`dsh headless -`），把答案原样带回来：

> 妈妈回你了：不用找输入框，也不要再去 page_do 里点评论框。直接调用 feiyu 的「发评论」动作……

问答都发生在**她那一轮对话里**，主人不需要转达。

## 妈妈能做什么

- 直接回答：知道她的工具表（看视频 / 搜 / 读网页 / 截图 / 发评论 / 认人 / 说 / 画 / 问妈妈）、
  项目根 `D:\qqaibot\astrbot`、插件目录、日志路径。
- 需要时读文件：只读，最多两个相关文件（读多了会慢到 88 秒，所以默认不读）。
- 不写文件、不重启服务、不发消息、不执行有副作用的命令——只回答。

## 妈妈没接上怎么办

助手进程起不来（没凭据、超时、dsh 找不到）时，问题会转发到 `mom_umo`，
主人回一句，她下一轮就能看到。这条兜底不依赖任何模型。

## 配置

| 配置项 | 默认 | 说明 |
| --- | --- | --- |
| `enable` | `true` | 总开关 |
| `dsh_cmd` | `dsh` | 可执行文件；PATH 找不到时自动试 DeepSeek Harness 自带的那份 |
| `work_dir` | `D:\qqaibot\astrbot` | 无头助手的工作目录 |
| `credentials_file` | `~/.dsh/.credentials.yaml` | 读 `refs.DEEPSEEK_API_KEY` 注入给无头运行 |
| `timeout` | `240` | 一次问话最多等多久（秒） |
| `max_answer_chars` | `400` | 回答最多留多少字 |
| `min_gap_seconds` | `20` | 两次问话的最短间隔 |
| `mom_umo` | 主人的私聊 | 兜底转发地址 |
| `mom_ids` | 空 | 还有谁的回话算数（QQ 号，逗号分隔；默认只有管理员） |

## 边界

- 妈妈只读不写：她问「帮我改一下」时，妈妈会说改哪里，动手还是主人来。
- 一次问话是一次独立运行，不保留上下文；追问要自己把前情写进 `question`。
- 凭据只在本机进程环境里注入，不写进任何日志。

## 会话放在哪（1.2.0）

DSH 的会话列表按工作目录分组。问妈妈如果每次都新建会话，就会像这样把列表刷满一堆「未分组」：

插件现在固定用 `mom_workspace`（默认 `D:\qqaibot\mom-workspace`）当工作目录，所以这些会话会集中进 DSH 里那个分组。
并且默认复用同一个会话（`mom_reuse_session = true`）：第一次问完把会话 id 记进 `mom_session_id`，之后都追加到同一条，
列表里只多一条，妈妈也记得上一句问了什么。

想让它每次都是全新的（不带上下文），把 `mom_reuse_session` 关掉；想重新开一条，把 `mom_session_id` 清空即可。
